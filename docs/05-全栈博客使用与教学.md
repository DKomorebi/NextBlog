# 拾页全栈博客：运行、权限与代码导读

当前版本已从静态 Demo 升级为 Next.js + Express + TypeScript + Tailwind CSS + PostgreSQL + TypeORM。此前 01–04 文档与已归档文章描述的是静态阶段；本篇和根目录 README 描述当前版本。

## 1. 运行项目

本机已按提供的连接配置创建独立数据库 `fieldnotes`，执行迁移并导入六篇示例文章。连接密码和随机 Session 密钥在根目录 `.env`，该文件已被 Git 忽略。不要覆盖已有 `.env`。

```powershell
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm db:seed
pnpm dev
```

`dev` 同时启动 Express（127.0.0.1:4000）和 Next.js（localhost:3000）。浏览器只访问 Next.js，`/api/*` 通过 next.config.ts 转发到 Express。由于同源，不需要把 Cookie 发送给另一个网站，也没有开放任意来源 CORS。

端口 3000 被占用时，请先关闭你自己先前启动的服务，或者设置 `.env` 的 APP_ORIGIN 为新地址，并以相同端口运行 `pnpm dev:web --port 3001`，另开终端运行 `pnpm dev:api`。APP_ORIGIN 必须与浏览器地址一致，包括 localhost / 127.0.0.1 的区别；不匹配会触发来源校验。修改环境变量后重启两个服务。

换电脑时先创建空的 PostgreSQL 数据库，再按照 `.env.example` 配置。也可以使用 compose.yaml 启动 PostgreSQL：在 `.env` 设置 POSTGRES_PASSWORD，并同步调整 DATABASE_URL；本机已运行 PostgreSQL 时不要占用同一个 5432 端口。

## 2. 管理员怎么获得权限

1. 在网站 `/register` 注册自己的账号。所有新账号始终是普通用户。
2. 在项目终端运行 `pnpm admin 你的注册邮箱`。
3. 刷新浏览器，导航出现“管理”，进入 `/admin`。
4. 点击“写一篇文章”，填写标题、唯一地址标识、分类、摘要和 Markdown 正文。

没有默认管理员密码，也没有“第一个注册用户自动变成管理员”的规则。只有能操作服务器终端的人能运行授权命令。测试用账号已清理，不要用测试账号登录。

| 操作 | 游客 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 阅读、搜索、分类、分页 | 允许 | 允许 | 允许 |
| 发表评论 | 需登录 | 允许 | 允许 |
| 删除自己的评论 | 不允许 | 允许 | 允许 |
| 删除他人评论 | 不允许 | 不允许 | 允许 |
| 新增、修改、删除文章 | 不允许 | 不允许 | 允许 |

前端隐藏按钮仅用于减少误操作。真正的限制位于 `server/app.ts` 的 requireUser / requireAdmin 中间件。每次请求都用 Session 中的 userId 查询数据库，角色变化会在下一次请求生效，客户端传入的 role、userId 不会被采信。

## 3. Cookie 和 Session 到底保存了什么

浏览器 Cookie 名为 `fieldnotes.sid`，保存签名后的随机 Session 标识。用户 ID 和 CSRF token 保存在 PostgreSQL 的 sessions 表中。退出会删除服务端会话并清除 Cookie；旧 Cookie 再次使用也无法恢复身份。重启 Express 不会清空登录状态。

当前配置使用 HttpOnly，阻止浏览器 JavaScript 读取登录 Cookie；SameSite=Lax 减少跨站携带；七天滚动有效期；生产模式额外启用 Secure，要求 HTTPS。登录及注册成功后调用 regenerate，更换 Session ID，随后显式保存，避免会话固定与重定向时的竞态。实现依据 [Express Session 文档](https://expressjs.com/en/resources/middleware/session/)。

`GET /api/auth/session` 返回当前用户的公开字段与 CSRF token。所有写操作都要求匹配的 Origin 和 `X-CSRF-Token`，注册、登录、退出也不例外。CSRF token 可以由页面脚本读取；它不是 Session Cookie，不能独立获得用户身份。

密码以 bcrypt 哈希保存，强度参数为 12；不存明文、不返回哈希。输入要求至少 10 个字符且最多 72 字节，后者避免 bcrypt 截断长密码。登录和注册有 IP 频率限制，评论另有频率限制。当前限流器存于单进程内存，多实例部署时应改为共享限流存储。

## 4. Markdown 阅读与编辑

`src/components/full-blog.tsx` 中的 Markdown 组件使用 react-markdown，配合 remark-gfm 支持表格、列表、删除线与任务列表；rehype-highlight 提供代码高亮。编辑器支持 `.md` 文件导入与实时预览。正文最大 200000 字符，文件导入最大 200KB，API 请求整体最大 256KB。

正文不会作为 HTML 字符串插入 DOM；skipHtml 禁用原始 HTML，链接使用库的默认安全 URL 处理。图片仅接受 HTTP(S) 或本站绝对路径，并设置不发送 Referer。Markdown 不支持 MDX、内嵌脚本或任意 HTML。[react-markdown 安全说明](https://github.com/remarkjs/react-markdown)

评论采用纯文本展示；昵称和内容均通过 React 的普通文本输出转义。当前不包含图片上传、富文本 HTML、嵌套回复、邮件验证、密码找回，这些可以独立加入下一阶段。

## 5. 请求链路与文件分工

```text
浏览器（SessionProvider / ArticleList / Editor / Comments）
   → /api/...，附 Cookie 和写请求 CSRF token
Next.js rewrite
   → Express：来源检查 → Session → 输入校验 → 权限检查
   → TypeORM Repository / QueryBuilder
   → PostgreSQL：users / articles / comments / sessions
```

| 文件 | 阅读重点 |
| --- | --- |
| src/components/full-blog.tsx | api 请求封装、Session Context、页面交互、Markdown 阅读与编辑 |
| src/app/*/page.tsx | 路由入口；动态文章不再需要 generateStaticParams |
| src/app/globals.css | 宣纸背景、墨青强调色、衬线标题、响应式布局 |
| server/entities.ts | EntitySchema：使用 TypeScript 类型描述数据库字段 |
| server/migration.ts | 建表、唯一约束、外键、索引及 Session 表 |
| server/db.ts | DataSource；synchronize 明确关闭 |
| server/app.ts | 认证、CSRF、角色校验、CRUD、错误处理 |
| server/manage.ts | 迁移、示例数据导入、管理员授权 |
| server/index.ts | 监听地址、配置加载、关闭连接 |
| server/app.test.ts | 使用独立临时数据库验证真实 PostgreSQL 行为 |

TypeORM 查询使用参数绑定。邮箱统一小写并建立唯一约束，slug 同样唯一；重复写入返回 409。评论的文章外键设置 ON DELETE CASCADE，删除文章同时删除评论。更新文章时要求提交 version，原子比较并递增版本，拒绝覆盖其他编辑者的更新。

迁移只在明确运行 `pnpm db:migrate` 时执行，服务启动不会自动改表结构。生产也不应开启 synchronize。[TypeORM 迁移配置](https://typeorm.io/docs/migrations/setup/)

## 6. 接口速查

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/auth/session | 获取登录状态与 CSRF token |
| POST /api/auth/register | 注册普通用户并登录 |
| POST /api/auth/login | 登录并更换 Session |
| POST /api/auth/logout | 注销 Session |
| GET /api/articles?q=&category=&page= | 搜索标题、摘要与正文，每页 10 篇 |
| GET /api/categories | 获取分类和数量 |
| GET /api/articles/:slug | 读取 Markdown 原文与文章信息 |
| POST /api/articles | 管理员新增文章 |
| PUT /api/articles/:id | 管理员更新文章，含 version |
| DELETE /api/articles/:id | 管理员删除文章 |
| GET /api/articles/:id/comments?page= | 读取评论，每页 30 条 |
| POST /api/articles/:id/comments | 登录用户发表评论 |
| DELETE /api/comments/:id | 作者或管理员删除评论 |

路径中的文章 id 是 UUID，slug 是给读者看的地址标识。写请求均使用 JSON。400 表示输入不合要求，401 表示未登录，403 表示无权限或 CSRF 失败，404 表示不存在，409 表示唯一键或编辑版本冲突，429 表示请求过于频繁。

## 7. 开发和生产的区别

本项目现在需要运行 Next.js 和 Express 服务，旧的 out 目录仅是此前静态 Demo 的产物，不应部署为当前网站。`pnpm build` 输出到 `.next-fullstack`，该路径隔离了旧的开发缓存。

本地学习使用 `pnpm dev`。生产流程为：设置 HTTPS 的 APP_ORIGIN 和随机 SESSION_SECRET；备份数据库；执行迁移；`pnpm build`；`pnpm start`。start:api 显式设置生产模式，启用 Secure Cookie，所以不能用纯 HTTP 验证生产登录。

生产反向代理需终止 HTTPS，转发正确的 X-Forwarded-Proto；Express 只监听 127.0.0.1，通过受控的 Next.js 代理访问。不要直接把 API 端口暴露到公网。使用独立低权限数据库账号，迁移与日常查询可以进一步分开授权。部署目录需包含 tsx 运行依赖（当前位于 devDependencies），因此 `pnpm start` 前不要使用省略 devDependencies 的安装方式。

## 2026-11-20：卡片、Lucide 与深色主题

文章列表恢复 DaisyUI 卡片边界和独立背景，图标使用项目已有的 lucide-react。导航、搜索、分类、日期、编辑、删除、评论和保存均有对应图标；图标标记 aria-hidden，操作仍保留文字或明确的可访问名称。

深浅主题通过 DaisyUI 的两个自定义主题实现。lib/theme.ts 中的首帧脚本优先读取保存偏好，没有偏好时跟随系统，避免刷新时闪白。ThemeToggle 同步系统变化和跨标签页存储事件。点击按钮时使用 View Transition 从按钮位置展开；键盘操作取按钮中心；不支持 API、减少动态效果或浏览器中断过渡时直接完成切换。localStorage 不可用也不影响切换。

头像/密码等信息不参与主题存储，localStorage 只记录主题名称。主题偏好与 Session 登录 Cookie 无关。
