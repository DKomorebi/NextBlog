# 从这个博客开始：Next.js、TypeScript 与 Tailwind CSS

这份文档面向第一次使用这些技术的实习生。所有标明路径的例子都对应当前项目；为解释概念而简化的代码会特别说明。建议一边打开源文件，一边运行 `pnpm dev` 观察变化。

## 1. 先理解各自的工作

| 技术 | 在项目中的职责 | 类比 |
| --- | --- | --- |
| HTML / JSX | 表达标题、段落、链接等内容结构 | 房子的骨架 |
| CSS / Tailwind CSS | 布局、颜色、间距、响应式 | 房间的摆放与装修 |
| JavaScript | 筛选、排序、点击事件等逻辑 | 电路和开关 |
| TypeScript | 在开发和编译阶段检查数据的形状 | 施工图中的规格 |
| React | 用组件描述 UI，状态变化后更新界面 | 可重复使用的房间模块 |
| Next.js | 基于 React 提供路由、构建、渲染和资源组织 | 把模块组织成完整建筑 |
| Express（下一阶段） | 接收 HTTP 请求、返回数据 | 服务窗口 |
| PostgreSQL（下一阶段） | 持久化存储文章等数据 | 档案库 |
| TypeORM（下一阶段） | 在后端将实体与表映射，帮助执行查询 | 数据访问工具 |

TypeScript 不是另一个 UI 框架；Tailwind 不是组件库；Next.js 也不是 Express 的别名。分清职责，才知道遇到问题应该检查哪里。

## 2. 如何启动，命令分别做什么

先阅读根目录 `package.json` 的 scripts：

```json
{
  "dev": "next dev --webpack",
  "build": "next build --webpack",
  "typecheck": "tsc --noEmit",
  "preview": "serve out -l 3000"
}
```

- `pnpm install`：根据依赖声明下载工具和库。已有锁文件时使用 `--frozen-lockfile`，避免无意改变依赖版本。
- `pnpm dev`：开发服务器。保存代码后通常自动刷新，适合修改和调试。
- `pnpm typecheck`：运行 TypeScript 检查，不输出 JavaScript。通过不等于页面交互一定正确。
- `pnpm build`：检查并构建生产版本。本项目还会生成静态页面到 `out/`。
- `pnpm preview`：提供 `out/` 中的已构建文件。修改源代码后，要重新 build 才能在 preview 看到变化。

`node_modules` 是下载的依赖；`.next` 是 Next.js 生成的中间产物；`out` 是可部署的静态结果。不要直接编辑这些目录，应该编辑 `src`。Next.js 的最低 Node.js 要求可以查阅[安装文档](https://nextjs.org/docs/app/getting-started/installation)。

## 3. 先补上 React / JSX 基础

### 3.1 组件就是返回界面的函数

打开 `src/components/header.tsx`，你会看到 `export function Header()`。函数返回 JSX：

```tsx
// 简化示例
export function Header() {
  return <header><h1>拾页</h1></header>;
}
```

组件名首字母大写；`<Header />` 使用组件，小写的 `<header>` 是原生 HTML 元素。`export` 允许其他文件导入它。JSX 里使用 `className` 而非 HTML 的 `class`，因为这是 JavaScript 中的属性名。

`.ts` 文件存放普通 TypeScript；`.tsx` 文件允许写 JSX。它们都需要工具处理后，浏览器才能使用。

### 3.2 花括号把数据带进界面

首页 `src/app/page.tsx`：

```tsx
const featured = posts[0];
// 以下 JSX 是首页中的片段
<h2>{featured.title}</h2>
```

`posts[0]` 取第一篇文章；`{featured.title}` 将字符串渲染出来。React 默认会转义文本，因此正文里出现 `<script>` 不会因为普通文本渲染而执行。不要为了显示文章随意改为 `dangerouslySetInnerHTML`；将来接入富文本需要另行设计清洗策略。

### 3.3 props 是传给组件的输入

首页使用：

```tsx
<PostBrowser posts={posts} />
```

子组件接收：

```tsx
export function PostBrowser({ posts }: { posts: Post[] }) {
  // ...
}
```

左边的 `posts` 是属性名，花括号中的 `posts` 是父组件变量。`{ posts }` 是 JavaScript 解构：从参数对象里取出这个属性；后面的 `{ posts: Post[] }` 是 TypeScript 注解，要求它是文章数组。子组件应该读取 props，不应直接修改父组件传来的数据。

### 3.4 列表与条件渲染

`post-browser.tsx` 中，`visible.map(...)` 把文章数组映射为卡片数组。每个卡片有 `key={post.slug}`，React 用稳定且唯一的 key 识别条目。不要在会排序的列表中用数组下标作为 key。

详情页的 `section.code && <pre>...</pre>` 表示有代码时才展示代码块；文章列表使用三元表达式 `visible.length ? 列表 : 空状态`。条件渲染就是让数据决定界面。

## 4. Next.js：目录如何变成网站

### 4.1 App Router 的文件约定

| 文件 | 浏览器地址 / 作用 |
| --- | --- |
| `src/app/page.tsx` | `/` |
| `src/app/about/page.tsx` | `/about/` |
| `src/app/archive/page.tsx` | `/archive/` |
| `src/app/posts/[slug]/page.tsx` | `/posts/nextjs-first-page/` 等 |
| `src/app/layout.tsx` | 包裹所有页面，不是单独地址 |
| `src/app/not-found.tsx` | 找不到页面时的展示 |

目录不一定就是页面：通常需要其中存在 `page.tsx`。`components` 下的组件不会自动变成 URL。`page.tsx` 需要默认导出页面组件。

### 4.2 layout 与 children

`src/app/layout.tsx` 的结构可概括为：

```tsx
<html lang="zh-CN">
  <body>
    <Header />
    {children}
    <footer>...</footer>
  </body>
</html>
```

`children` 是当前路由对应的内容。打开首页时放入 Home，打开归档时放入 Archive。这样每个页面不必重复写导航和页脚。`lang` 告诉辅助技术页面语言；`metadata` 提供浏览器标题与描述，不是界面上的可见标题。

### 4.3 Link 与普通 a

内部页面导航用 `next/link` 的 `Link`，例如 `<Link href="/archive/">归档</Link>`。Next.js 能据此优化内部导航。跳转同页目录锚点使用普通 `<a href="#section-0">` 就足够。

### 4.4 服务端组件与客户端组件

App Router 中组件默认是服务端组件。首页、详情页、归档不需要处理本地交互，所以没有 `"use client"`。

`src/components/post-browser.tsx` 顶部写了：

```tsx
"use client";
import { useState } from "react";
```

它需要 `useState`、输入事件和点击事件，因此声明为客户端入口。这个边界下的代码会进入浏览器包。不要在其中导入数据库连接或服务器密钥。

**“服务端组件”不表示本项目上线后必须一直运行 Node.js 服务。** 当前启用了静态导出，这些组件在 build 时执行。客户端组件也可以参与初始 HTML 预渲染，随后浏览器加载 JavaScript 并接管事件，这个过程称为 hydration。并不是写了 `use client` 就意味着初始页面完全没有 HTML。[官方说明](https://nextjs.org/docs/app/getting-started/server-and-client-components)

为什么不把整个首页都标记为客户端组件？因为只有列表需要交互。把边界放在较小的组件上，更容易看清哪些逻辑属于浏览器。

### 4.5 动态路由：slug 是什么

打开 `src/app/posts/[slug]/page.tsx`：

```tsx
type ArticleProps = { params: Promise<{ slug: string }> };

export default async function Article({ params }: ArticleProps) {
  const { slug } = await params;
  const post = getPost(slug);
  if (!post) notFound();
  // 后续返回文章 JSX
}
```

访问 `/posts/typescript-data-model/` 时，slug 对应 `typescript-data-model`。当前 Next.js 的 params 是异步参数，因此先 `await`。`Promise<T>` 表示将来会得到一个 T 类型的结果；包含 await 的函数要声明为 async。

`getPost` 使用 `find` 查询，结果可能是 `Post`，也可能是 `undefined`。不存在时调用 `notFound()` 结束当前页面渲染；检查之后 TypeScript 知道 post 已存在，后面的 `post.title` 才能安全访问。

### 4.6 静态导出为什么需要 generateStaticParams

`next.config.ts`：

```ts
const nextConfig: NextConfig = {
  output: "export",
  trailingSlash: true,
};
```

详情路由：

```tsx
export function generateStaticParams() {
  return posts.map((post) => ({ slug: post.slug }));
}
```

构建器必须知道所有文章地址，才能逐个生成 HTML。`trailingSlash` 让文章输出为类似 `out/posts/typescript-data-model/index.html`，适合按目录提供静态文件。新增文章后重新构建，就会生成新路径。

没有 Node.js 请求处理服务，就不能依赖请求时读数据库、Server Actions 或运行时动态生成未知文章。静态页面仍可以通过浏览器请求独立 API，但新增详情地址仍需重建，或者改变路由与部署方案。[静态导出文档](https://nextjs.org/docs/app/guides/static-exports)

## 5. TypeScript：给数据和函数写约定

### 5.1 基础类型与数组

`src/types/post.ts` 里的 `title: string` 是字符串，`minutes: number` 是数字，`tags: string[]` 是字符串数组。属性类型不是默认值，它只描述允许出现的值。

```ts
const minutes: number = 6;
// const minutes: number = "6"; // 故意写错：字符串不能赋给数字
```

不是每个变量都要显式标注。`const [query, setQuery] = useState("")` 可以从空字符串推断 query 是 string。[基础类型参考](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html)

### 5.2 interface 描述对象形状

当前项目的实际定义：

```ts
export interface Section {
  heading: string;
  paragraphs: string[];
  code?: string;
}
```

每一节都必须有 heading 和 paragraphs；`code?` 可以不存在。可选属性读取后可能是 undefined，因此展示时先判断。`Post` 则把标题、摘要、分类、日期、标签和正文小节组合成完整文章。

`export const posts: Post[] = [...]` 会检查数组中的每一个对象。如果漏写 title，或者 minutes 写成文字，编辑器和 `pnpm typecheck` 会提示具体位置。这是我们把模拟数据也写上类型的原因。

### 5.3 联合类型限制可选值

```ts
export type Category = "前端开发" | "后端探索" | "成长手记";
```

竖线表示“或者”。分类不是任意字符串，而是这三个值之一。筛选器还需要“全部文章”，所以使用：

```tsx
const [category, setCategory] =
  useState<Category | "全部文章">("全部文章");
```

`<...>` 是泛型参数，告诉 useState 允许保存什么值。“全部文章”是筛选器状态，不是某一篇文章的真实分类，所以没有加入 Category 本身。

### 5.4 函数返回值与 undefined

```ts
export function getPost(slug: string): Post | undefined {
  return posts.find((post) => post.slug === slug);
}
```

括号里的 `slug: string` 限制输入，括号后的 `: Post | undefined` 描述输出。find 只返回第一条匹配数据，找不到时返回 undefined。不要用 `as Post` 强行抹掉“找不到”的可能性，应该处理这个分支。

### 5.5 读懂几种常见语法

| 项目写法 | 含义 |
| --- | --- |
| `import type { Post }` | 只导入类型，运行时不需要这个值 |
| `Post["cover"]` | 从 Post 中取出 cover 属性的类型，避免重复定义 |
| `post?.title` | post 不存在时返回 undefined，不继续读取 title |
| `post?.title ?? "文章不存在"` | 左边是 null 或 undefined 时使用默认值 |
| `Readonly<{ children: React.ReactNode }>` | 限制参数对象的属性赋值，children 可包含 React 可渲染内容；它不是深层冻结 |
| `@/types/post` | 路径别名；由 tsconfig 的 paths 映射到 src/types/post |

### 5.6 strict 与编译的边界

`tsconfig.json` 的 `strict: true` 打开严格检查；`noEmit: true` 表示 TypeScript 检查过程不输出文件，实际编译交给 Next.js。不要为了消除报错随意关掉 strict 或添加 any。

TypeScript 的类型在运行时会消失。将来写 `const data: Post[] = await response.json()` 并不能证明服务器返回的 JSON 符合 Post。API 输入和输出需要运行时校验，这是后端接入阶段的新工作。

## 6. Tailwind CSS：用组合表达样式

### 6.1 本项目使用 v4 配置

`postcss.config.mjs` 注册 `@tailwindcss/postcss`，`src/app/globals.css` 首行是：

```css
@import "tailwindcss";
```

Tailwind 在构建时扫描源代码中的类名，生成对应 CSS。因此它不是运行时逐条翻译 className。v4 的配置方式与很多旧版教程不同，不要混用 v3 的安装命令和配置。[官方 Next.js 安装指南](https://tailwindcss.com/docs/installation/framework-guides/nextjs)

### 6.2 拆开一张卡片

`post-browser.tsx` 中卡片的类名可以按作用阅读：

```tsx
className="group overflow-hidden rounded-2xl border border-line
           bg-white/60 transition-colors hover:border-accent/50"
```

| 工具类 | 对应的视觉作用 |
| --- | --- |
| `overflow-hidden` | 裁切超出卡片的封面，让圆角生效 |
| `rounded-2xl` | 较大的边框圆角 |
| `border border-line` | 细边框，使用项目主题颜色 |
| `bg-white/60` | 60% 不透明度的白色背景 |
| `transition-colors` | 颜色变化使用过渡 |
| `hover:border-accent/50` | 悬停时改变边框颜色 |
| `group` | 让子元素可以响应父级的悬停状态 |
| `group-hover:text-accent` | 父卡片悬停时，子标题改变颜色 |

这些类可以组合；仍然需要理解 box model、flex、grid、overflow 等 CSS 概念。Tailwind 让你少起很多类名，但不会替你决定合理布局。

### 6.3 响应式从小屏幕开始

文章列表：

```tsx
className="grid grid-cols-1 gap-x-6 gap-y-8 md:grid-cols-2"
```

基础是一列；到默认 md 断点（48rem）及以上变成两列。首页外层用了 `lg:grid-cols-[minmax(0,1fr)_260px]`：宽屏时左侧占剩余空间，右侧固定 260px；更窄时回到单列。`minmax(0,1fr)` 允许主内容缩小，避免长内容强行撑宽网格。

`hidden md:flex` 表示小屏隐藏装饰，中等及以上屏幕显示 flex。注意 md 不是“只在平板”，而是“达到该宽度以及更宽”。

### 6.4 间距、字号与任意值

默认间距基于 0.25rem：`p-6` 通常是 1.5rem 内边距，`mt-5` 是 1.25rem 上边距。`text-sm` 同时设定字号和行高；正文使用 `leading-8` 增加阅读间距。

方括号允许任意值，例如 `text-[11px]`、`min-h-[65vh]`。应优先使用统一的设计尺度，再在确实需要时使用任意值，避免每个元素都有不同的数值。

### 6.5 主题变量与自定义 CSS

在 `globals.css` 中：

```css
@theme {
  --color-paper: #f8f7f3;
  --color-ink: #272b27;
  --color-accent: #526545;
}
```

Tailwind 据此提供 `bg-paper`、`text-ink`、`border-accent` 等类。修改一个变量即可调整整个网站的对应颜色。

封面的轨道装饰、网格纹理属于重复而具体的视觉样式，所以放进 `.cover`、`.cover-orbit` 和 `.hero-grid` 等普通 CSS 类。Tailwind 可以与普通 CSS 共存，不需要强迫一切都写成工具类。

### 6.6 不要拼接无法扫描的类名

不建议写 `bg-${color}-500`。构建器不执行你的 JavaScript 来枚举所有可能字符串，因此可能漏掉样式。使用完整类名映射，例如 `{ green: "bg-green-500", blue: "bg-blue-500" }`。

本项目 `cover-${kind}` 对应的样式是 globals.css 中明确写出的普通 CSS 规则；不是期待 Tailwind 自动生成这些动态类。分类按钮的三元表达式则包含两组完整的工具类字符串，可被扫描。

## 7. 把一次搜索从头跟到尾

阅读 `src/components/post-browser.tsx`，按下列顺序跟踪：

1. `useState("")` 保存搜索文本 query，初始为空。
2. input 的 `value={query}` 让 React 状态成为输入内容的来源，这叫受控输入。
3. 用户键入内容，onChange 用 `event.target.value` 读取新文本。
4. `setQuery(...)` 请求 React 更新状态并重新渲染组件；不是立刻修改当前函数中的变量。
5. 组件重新执行 filter，生成新的 visible。
6. map 将 visible 变成卡片，React 更新页面中变化的部分。

实际筛选逻辑：

```tsx
const matchesCategory = category === "全部文章" || post.category === category;
const matchesQuery = `${post.title} ${post.excerpt} ${post.tags.join(" ")}`
  .toLowerCase()
  .includes(query.trim().toLowerCase());
return matchesCategory && matchesQuery;
```

`||` 表示任一条件成立；`&&` 表示两个条件都成立。分类和搜索必须同时匹配。join 将标签数组拼成可搜索文本，trim 去掉搜索首尾空格，toLowerCase 统一大小写。

filter 返回新数组，因此后面的 sort 不会修改原始 posts。若直接对 props 中的 posts 调用 sort，就会原地改变它。本项目日期统一使用补零的 `YYYY-MM-DD` 格式，所以字符串比较也能按日期排序。

visible 是派生结果，不需要再存进一个 useState；否则每次更新 query 和 category 都要同步它，容易出现状态不一致。只有六条数据，也没有必要先引入 useMemo 或搜索库。真实大量数据则应在服务端分页和搜索。

## 8. 如何增加第七篇文章

1. 打开 `src/lib/posts.ts`，在 posts 数组中复制一篇结构完整的文章。
2. 使用新的、唯一的 slug，例如 `my-first-component`。
3. 修改 title、excerpt、date、tags 和 sections。category 必须使用已有三个值之一；cover 必须使用 Post 中约定的封面键。
4. 运行 `pnpm typecheck`。如果类型报错，按提示补齐字段。
5. 在 dev 中查看首页，再直接访问 `/posts/my-first-component/`。
6. 运行 `pnpm build`，确认 out 中出现新路径，再用 preview 检查。

扩展思考：首页“小站数字”和归档年月目前是为六篇 2026 年 11 月示例文章写的展示内容。添加其他日期的文章时，应将统计和归档分组改为数据驱动，而不是只改数字。相关练习见验收文档。

## 9. 如何调试常见问题

| 症状 | 优先检查 |
| --- | --- |
| 找不到 pnpm | 确认包管理器安装和终端 PATH；也可按 README 使用 npm |
| 安装报 EACCES / 网络超时 | 检查工作环境网络权限、代理和项目 .npmrc，不要盲目改业务代码 |
| useState 相关的组件报错 | 文件是否需要声明 `"use client"`，是否错误地在服务端使用浏览器功能 |
| 新文章直接打开 404 | slug 是否正确、是否新增到 posts、是否重新 build、静态服务是否支持目录 index.html |
| 修改后 preview 不变 | preview 展示 out，需要重新 build |
| Tailwind 类无效果 | globals.css 是否导入、PostCSS 插件是否正确、类名是否完整可扫描 |
| 浏览器出现横向滚动 | 检查固定宽度、长代码和 grid 子项最小宽度 |
| port 3000 已占用 | 关闭自己的旧服务，或开发时使用 `pnpm dev --port 3001` |

开发时先读终端报错，再看浏览器控制台。一次只改一个原因明确的点。不要同时升级依赖、修改配置和改业务代码，否则难以知道哪一项解决了问题。

## 10. 推荐阅读顺序与自测

第一轮只读 `types/post.ts → lib/posts.ts → components/cover.tsx → app/page.tsx`，理解数据如何展示。第二轮读 `post-browser.tsx`，理解状态与事件。第三轮读动态详情路由和构建配置，理解 URL 与静态导出。

当你能不用看文档回答这些问题，就具备继续接后端的基础了：为什么 slug 不能重复？为什么搜索组件需要 use client？为什么 TypeScript 不能校验未知 JSON？为什么静态站新增文章要重建？为什么 filter 后再 sort 不会修改原数组？为什么 md 不是设备类型？

文中的 API 约定参考了上述官方文档。具体项目行为以本仓库代码、锁文件与实际构建结果为准，后续升级版本时应重新检查迁移说明。
